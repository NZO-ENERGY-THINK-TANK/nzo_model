# reference/

תרחיש הייחוס: בדיקת רגרסיה (regression test) מקצה לקצה. מריצה Roadmap קבוע ומשווה את התוצאות לערכים שהוקלטו. כך רואים כל שינוי בתוצאות המודל, בקוד או בנתונים, גם אם לא התכוונו אליו.

## מה נבדק
- Roadmap `Base`, 6 שנות מפתח (2026, 2030, 2035, 2040, 2045, 2050): סולארי, רוח ואגירה בלבד.
- 20 ערכים: NPV כולל ורכיביו (סולארי, רוח, אגירה, גז, חיצוניות), נתח מתחדשות מרבי, שיא הספק גז, ובשנים 2030, 2040, 2050: נתח מתחדשות, ייצור גז, שיא הספק גז ועלות שנתית.
- סבילות יחסית: 1e-6.
- ההרצה לא כותבת לשום לשונית.

## איפה הקוד
- `src/reference_test.js`: הפונקציות `runReferenceTest()` ו-`recordReferenceTest()`, וה-keyframes של התרחיש (מוטמעים בקוד, לא תלויים בגיליון).
- `src/reference_test_expected.js`: הערכים הצפויים (`REFERENCE_EXPECTED`).
- בתפריט בגיליון: NZO Model ← Advanced ← Run reference test / Record reference test.

## תוצאות אפשריות
| תוצאה | משמעות |
|---|---|
| `PASS` | כל הערכים תואמים |
| `FAIL` | יש הפרש. מוצגים הערך הצפוי, בפועל והפרש באחוזים |
| `INPUT CHANGED` | פרמטרים ב-`01_parameters` (ריבית, שעות ייצור וכו') שונים מאלה שהוקלטו, וההשוואה אינה תקפה. מחזירים את הפרמטרים |
| `NO EXPECTED` | אין ערכים צפויים. מריצים `recordReferenceTest` |

## נוהל
1. **PR של קוד:** מריצים `runReferenceTest` ומצרפים את התוצאה לתיאור ה-PR. `PASS` נדרש, אלא אם השינוי בתוצאות מכוון.
2. **PR של נתונים (`data/`):** מצרפים ΔNPV (ההפרש ב-`totalCost` בין לפני לאחרי), כי תוצאת הייחוס תשתנה. מעדכנים את הערכים הצפויים (סעיף 3).
3. **שינוי מכוון בתוצאות:** מריצים `recordReferenceTest`, מעתיקים את ה-JSON שמוצג ל-`src/reference_test_expected.js`, ובאותו PR מסבירים למה התוצאות השתנו. ה-diff מראה אילו ערכים השתנו.
4. **עורכים רק בקבצים המקומיים ומעלים עם `clasp push`.** עריכה בעורך של Apps Script עלולה להשאיר גרסה לא מעודכנת.

## אימות המבחן
ב-2026-10-10 שינוי הסולארי של 2026 מ-8000 ל-8100 גרם ל-`FAIL` (NPV: 0.0044%, `solarCost`: 0.105%), וההחזרה ל-8000 החזירה `PASS`.
